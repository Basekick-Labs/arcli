### Added

- `arcli rbac organization`, `team`, `role`, `measurement`, and `token team` manage Enterprise RBAC resources and token team memberships. Lists support table, JSON, and CSV output; destructive changes prompt for confirmation. Token commands accept an id or exact name. Table and CSV timestamps are UTC RFC3339 by default; `--time-output rfc3339nano` shows fractional seconds. JSON retains available timestamp precision. Prompts and warnings name the object and flag changes that widen access: deleting a role's last measurement permission, removing a token's last team, and deleting a team or organization (see "RBAC access safety" in the README). `--permission` accepts comma-separated values. A missing route reports the server's HTTP 404 error with the neutral hint described under Changed. Closes [arcli#27](https://github.com/Basekick-Labs/arcli/issues/27).
- `arcli governance policy` manages per-token query limits, and `arcli governance usage` shows current usage on Enterprise servers with query governance enabled. Policies and counters are per-node, not replicated; behind a load balancer, aggregate quotas can be N times the configured limit. An admin token is required when authentication is enabled. Policy updates preserve omitted limits but concurrent read-then-write updates can lose changes. Zero means unlimited; omitted create limits override server defaults with unlimited, and flagless creates require `--unlimited`. Policy lists resolve token names when available; usage distinguishes unlimited limits, untracked counters and server defaults. Orphan policies can be shown/deleted by numeric token ID. Timestamps in table, CSV and text output use UTC RFC3339 by default; `--time-output rfc3339nano` shows fractional seconds, and JSON keeps the precision the server sent. A missing route reports the server's HTTP 404 error with the neutral hint described under Changed. Closes [arcli#29](https://github.com/Basekick-Labs/arcli/issues/29).

- `arcli admin query active`, `history`, `show`, and `cancel` expose Arc's query-management API. Lists support table, JSON, and CSV output; history accepts `--limit`, and cancellation prompts unless `--yes` is supplied. The commands require an admin token when authentication is enabled and the Arc Enterprise `query_management` feature. Table and CSV timestamps are UTC RFC3339 by default; `--time-output rfc3339nano` shows fractional seconds. CSV headers are lower snake_case (`id`, `status`, `token`, `remote_addr`, `start_time`, `duration_ms`, `sql`, `forwarded_to`; `history` adds `end_time` and `row_count`) and CSV keeps the original SQL text, including line breaks; JSON preserves the original response. A missing route reports the server's HTTP 404 error with the neutral hint described under Changed. Query management is per node: target the node that runs the query. Requests are not forwarded, and history is lost on node restart. History is bounded by `query_management.history_size` (100 by default), even with a larger `--limit`. Active lists are sorted oldest first. List tables show SQL on one line (line breaks and tabs become spaces) shortened to 120 characters; `show` keeps the full SQL (Arc itself cuts active-query SQL to 200 bytes). Arc 26.09.4 does not report `forwarded_to`, so that column stays empty. The cancellation prompt names the target endpoint, and a cancel that Arc answers with `Query not found` adds a hint to target the node that runs the query. Closes [arcli#30](https://github.com/Basekick-Labs/arcli/issues/30).

- Added `arcli mqtt` commands for health and aggregate stats, plus MQTT subscription list/show/create/update/delete, lifecycle actions, and per-subscription stats. List output supports table, JSON, and CSV; object output supports table and JSON. Create/update config is read from JSON files or stdin so credentials do not need to appear in process arguments; private file permissions are required when credentials are present, and subscription output omits usernames, broker URL userinfo, and sensitive query values. Malformed broker URLs and known request passwords are scrubbed from server errors, and the detail of an Arc parse error for a credential-bearing broker URL is withheld. On Windows, use stdin for credential-bearing configuration. String and object topic-mapping rules are supported. Health exits nonzero when unhealthy/degraded (0 when MQTT is disabled), and create exits nonzero when the subscription has error status. Delete, stop, pause, and restart prompt for confirmation. CSV preserves non-secret values separately from terminal sanitization. Table and text timestamps use UTC RFC3339 by default; `--time-output rfc3339nano` shows fractional seconds, and JSON keeps the precision the server sent. A missing route reports the server's HTTP 404 error with the neutral hint described under Changed, without a config key (Arc registers the MQTT routes even when MQTT is disabled, which answers HTTP 503 with the server's message). Closes [arcli#35](https://github.com/Basekick-Labs/arcli/issues/35).

- Add `arcli tiering` commands for status, bounded file listings, migration, scans, statistics, and per-database policy management. File and policy lists support table, JSON, and CSV output; object commands support table and JSON. Policy input validates database names and non-negative age values; `policy set` requires at least one policy flag and documents its full-replacement semantics (omitted fields reset). Policy deletion and every form of `tiering migrate`, including `--dry-run`, prompt for confirmation unless `--yes` is passed, and refuse a non-interactive stdin without it. Arc 26.09 and earlier ignore `--dry-run`, `--database` and `--measurement` on `tiering migrate` and run a real, full, unfiltered migration cycle over every eligible file; the prompt for those forms says so, and when the response shows it happened arcli warns on stderr and exits non-zero. Tier statistics accept Arc's tier-keyed object and show sorted tier totals. Storage error credentials are redacted in every output format, failed scans retain partial results, and timeouts explain that work continues server-side. Arc currently exposes only a limit for tiered file listings, with no offset or cursor; in `tiering file -o json`, `count` is the number of files returned, not the total. CSV preserves original values with lowercase snake_case headers. Table, CSV and text timestamps use UTC RFC3339 by default; `--time-output rfc3339nano` shows fractional seconds, and JSON preserves the server response except for backend credential redaction. A missing route reports the server's HTTP 404 error with the neutral hint described under Changed. Closes [arcli#28](https://github.com/Basekick-Labs/arcli/issues/28).

- `arcli backup restore --mode merge|replace` (default: Arc's own). The value is case-insensitive and trimmed, as Arc does; an invalid value is rejected before any request, and a blank one is treated as omitted (no mode is sent). Output names the mode only when Arc reports `replace`, so a merge restore prints exactly what earlier releases printed, and the confirmation prompt is unchanged when `--mode` is omitted or `merge` for an unscoped backup and for any backup from a server without `scope`. The `--mode replace` prompt states what Arc 27.01.1+ (currently unreleased) does on a cluster: it first removes the current hot-tier files of the restored databases on every node, including data written after the backup, then restores the backup's files; standalone servers refuse replace and older Arc versions merge. For a scoped backup restored without `--mode`, the prompt names the scope and says that a cluster running Arc 27.01.1+ (with `cluster.raft_data_dir`) restores it as replace, and that Arc refuses the replace of an incomplete backup only after accepting the restore. After a 202 that reports `replace` without `--wait`, arcli warns on stderr that Arc checks the backup's files only after accepting it; stdout and the exit code are unchanged. arcli refuses `--mode replace` before the prompt when Arc would refuse it: a manifest that records data gaps, more than 10% of the listed data files missing from the cluster manifest (`unregistered_skipped`, as Arc computes it), or a scoped backup that holds no data files for one of its databases; for that last case without `--mode`, the prompt says a cluster answers HTTP 400. `backup show` prints a `scope:` line, and `backup list` marks scoped backups as `full (scoped)` in the table and appends `scope` to CSV. `backup list` counts `manifest_only_files` as INCOMPLETE and adds `unregistered_skipped`, `manifest_only_files` and `left_manifest_during_run` at the end of existing CSV columns. `backup show` and restore status also print the cluster-manifest samples, and `backup show` excludes skipped files the cluster manifest later dropped (`skipped_reconciled`). Current Arc listings also carry that count, so list and show both subtract reconciled skips; CSV appends `skipped_reconciled`. Explicit modes require Arc 27.01.1+. Older servers ignore `--mode` and merge, so an unechoed `--mode merge` is accepted, while an unconfirmed or mismatched `--mode replace` returns a warning and a nonzero exit. An accepted restore may still run: inspect status before retrying. Creation progress includes manifest-only gaps. Part of [arcli#44](https://github.com/Basekick-Labs/arcli/issues/44); closes [arcli#85](https://github.com/Basekick-Labs/arcli/issues/85).
- `cluster status` shows active or expired cluster-wide compaction pause leases, including the requester, reason, lease expiry, and pending acknowledgements. Lease expiry is renewed and is not the pause end time. `backup restore --wait` reports observed pause-state transitions (polling may skip intermediate states), including a hint when the pause is lost, and `compaction trigger` preserves Arc's cluster-wide paused response instead of reporting that another cycle is running. `compaction stats` adds `paused cluster-wide by a restore` to its cycle line while Arc reports the pause. Arc 27.01.1+ (currently unreleased) pauses compaction and registers restored files cluster-wide. Older clusters, including 26.06–26.09, require manually stopped compaction and do not register restored files; standalone servers also need manually stopped compaction. JSON cluster output remains unchanged. Part of [arcli#44](https://github.com/Basekick-Labs/arcli/issues/44).
- `arcli scheduler cq reload` reloads all active continuous queries into the scheduler (it does not execute them; `arcli cq execute` runs one query). Each node keeps its own CQ jobs and only the primary writer runs them; reload the primary writer (and any node that may take over). Arc's error status and message are preserved; the status codes depend on the Arc version (see the README). Closes [arcli#33](https://github.com/Basekick-Labs/arcli/issues/33).
- `arcli scheduler retention trigger` runs all active retention policies immediately, after a confirmation prompt (`--yes` skips it). Only the primary writer of a cluster runs it. If arcli stops waiting (`--timeout` or ctrl-C), it says that the run may still be going server-side and points to `arcli retention executions`. Arc's error status and message are preserved; the status codes depend on the Arc version (see the README). Closes [arcli#33](https://github.com/Basekick-Labs/arcli/issues/33).
- `arcli audit log` queries Enterprise audit records with event, actor, database, time, and pagination filters; `arcli audit stats` reports event counts. Both require an Enterprise license with audit logging enabled, and an administrator token when Arc authentication is enabled. Each node keeps its own audit records; on a cluster a command shows only the node it reaches. Table and CSV timestamps, including the displayed `audit stats` since value, use UTC RFC3339 by default; `--time-output rfc3339nano` shows fractional seconds, and `-o json` returns the server response unchanged. A missing route reports the server's HTTP 404 error with the neutral hint described under Changed. Closes [arcli#31](https://github.com/Basekick-Labs/arcli/issues/31).
- `arcli cluster files` reads the cluster file manifest in bounded pages (1,000 entries by default, up to 10,000). Filter with `--database`, continue with `--cursor` from the previous page's `next_cursor`, and choose table, JSON, or CSV output. Responses without `next_cursor` are rejected rather than treated as complete pages. Table and CSV timestamps are UTC RFC3339 by default; `--time-output rfc3339nano` shows fractional seconds. Use `--no-header` to suppress column headers in table or CSV output. CSV writes sizes in bytes and string fields verbatim (no control-character cleaning, unlike the table); JSON preserves the original response, including pagination. Closes [arcli#32](https://github.com/Basekick-Labs/arcli/issues/32).
- `arcli license status` inspects the public `/health` license block on standalone and clustered Arc deployments, with table and JSON output. Reports tier, server status, source, and optional expiry, days remaining, and site-license state. Table expiry uses UTC RFC3339 in whole seconds, like every other arcli timestamp (`--time-output rfc3339nano` shows fractional seconds); JSON keeps the fractional seconds.
- Absent/null license blocks succeed as normal OSS behavior and produce `{"configured":false,"license":null}` in JSON. Present licenses produce `{"configured":true,"license":{...}}`, preserving active, expired, invalid, unlicensed, and unknown server statuses. Optional absent/null fields are omitted; explicit zero days and false site-license values are retained.
- All successfully read license states exit 0. Configuration, request, decoding, and output failures exit nonzero. No token or database header is sent to `/health`, and no authentication verification is performed. Normal connection selection, timeout, TLS verification, and identity opt-out settings apply.
License installation and key/file configuration remain server responsibilities. Existing `ping -o json` license pass-through is unchanged. Closes [arcli#34](https://github.com/Basekick-Labs/arcli/issues/34).

- `--time-output rfc3339|rfc3339nano` on every command that shows timestamps in table, CSV or text: `retention list|show|create|update|execute|executions`, `cq list|show|create|update|execute|executions`, `backup list|show|status|create|restore|delete` (including the `--wait` progress and the confirmation prompts), `cluster status|nodes|node show`, `logs`, `scheduler status`, `auth whoami`, `auth token list|show`, `compaction status` and `license status`, plus the new `audit`, `cluster files`, `governance`, `admin query`, `rbac`, `mqtt` and `tiering` commands listed above. The default, `rfc3339`, keeps the output (table, CSV, text, prompts) byte for byte what earlier releases print: UTC with whole seconds; only the commands' `--help` gains the flag. `rfc3339nano` keeps the sub-second precision the server reports, with trailing zeros trimmed, so values vary in width and do not sort lexically. Values are case-insensitive and an invalid value fails before any request is sent. `-o json` is unaffected (it already carries full precision) and the flag is accepted there with no effect. Timestamps that arcli has always passed through as the server sent them are left as they are and do not take the flag: `db list|show|create`, `import`, `sample show`, and `arcli query` results.


### Changed

- `arcli backup` commands: when the backup routes are not registered, the existing message `backups are disabled on this server (backup.enabled=false)` is now followed by `; if backup.enabled is true, the backup manager failed to initialize (see the server log)`. Arc also leaves those routes unregistered when the backup manager fails to initialize, so the configuration value alone could be wrong. The original text is unchanged and still comes first, so scripts that search for it as a substring or prefix keep matching; scripts that compare the whole line, or anchor a match to its end (for example `grep 'enabled=false)$'`), must be updated. Exit status (1) and error type are unchanged. Retention and continuous-query messages are unchanged.
- Feature groups added after this release (none are released yet) report a missing route as the server's HTTP 404 error followed by a neutral hint, instead of asserting `<feature>.enabled=false`. The hint is part of the error text and reads `; Arc is reachable but did not register this route; check <config key>, the license, the server log, and that this Arc version supports this command`, or without `<config key>, ` for groups whose routes do not depend on a configuration key. Example: `arc: Cannot GET /api/v1/tiering/files (HTTP 404); Arc is reachable but did not register this route; check tiered_storage.enabled, the license, the server log, and that this Arc version supports this command`. The published retention, continuous-query, and backup messages are kept.

### Fixed

- `arcli compaction trigger --wait` prints the waited cycle's own result instead of the server's lifetime totals. Before: `Cycle 4 finished: 1 jobs completed, 0 failed, 24.3 KiB saved in total` for a cycle that compacted nothing. Now: `Cycle 4 finished: 0 of 0 batches compacted, 0 failed`, from Arc's `last_cycle` record (Arc 26.09.2+), followed when non-zero by interrupted and unstarted batches, discovery errors and partitions skipped as too wide, and by the status when it is not `completed`. This published line changes because it was the bug: Arc reports per-cycle counts only as batches and has no per-cycle jobs or bytes, so `jobs completed` and `saved in total` are dropped; `Cycle N finished` and `N failed` are kept. When the record is another cycle's, or the server is older than 26.09.2, the line gives no counts. `-o json`, stderr, error texts and exit status are unchanged. Closes [arcli#96](https://github.com/Basekick-Labs/arcli/issues/96).
- `arcli cq executions -o csv`, `arcli retention executions -o csv` and `arcli compaction history -o csv` write the server's error text verbatim. They stripped newlines, tabs and other control characters from it, so a multi-line error lost its line breaks and ran its words together. CSV output is a data export and, like the other CSV exports, is written verbatim and not sanitized for terminals (encoding/csv quotes multi-line values but passes escape and bidi characters through). A missing or empty error is still `-`, the `failed: ` prefix in compaction history is unchanged, and the table output still strips control characters. Closes [arcli#94](https://github.com/Basekick-Labs/arcli/issues/94).
- `arcli cluster node remove` against a follower names a leader address with a host when the leader binds every interface. Such a leader publishes its API address without a usable host (`:8000`, `0.0.0.0:8000` or `[::]:8000`), and the hint printed it as is (`http://:8000`). Like Arc's own forwarding, arcli now takes the host from the leader's cluster address and keeps the API port, so `:8000` with cluster address `arc-writer1:9100` gives `http://arc-writer1:8000`, and the hint says the host was taken from the cluster address. IPv6 hosts are bracketed. Any unspecified IP spelling (`0.0.0.0`, `::`, `::0`) counts as no host. Unlike Arc, an unspecified or zoned (`fe80::1%eth0`) cluster host is not used. In that case, or with no cluster address, the hint names the API port instead: `the leader is node "n2" (API port 8000; its host is not published); find its address with arcli cluster nodes`. A leader with no API address at all keeps the existing "find its API address with `arcli cluster nodes`" text. An API address with an explicit host prints exactly as before. Closes [arcli#94](https://github.com/Basekick-Labs/arcli/issues/94).
- `arcli cq execute --end` warns about rewinding the query's watermark by comparing the value actually sent to the server. arcli sends `--end` with its fractional seconds dropped, but compared the untruncated value with the last processed time, so a fractional `--end` that rounded down below the watermark rewound it without a warning. Those cases now warn, with a message that names the typed and the sent value: `warning: --end <typed> is sent as <sent> (whole seconds), which is earlier than the query's last processed time <last processed>; ...`. Every case that warned before keeps its exact text, and whole-second `--end` values (the documented form) behave and print exactly as before.
- Preserve exact integer timestamps in JSON writes when decimal or exponent notation is used. Fractional timestamps are rejected without floating-point rounding, and both int64 boundaries are accepted when represented exactly.
- Accept large integers that can be represented exactly as float64 in mixed numeric JSON write columns. Lossy conversions remain rejected, and integer-only columns retain int64 encoding.
- `arcli query` (table, CSV and JSON) prints integers above 2^53 exactly. They were decoded as float64, so a `BIGINT` such as `9007199254740993` printed as `9007199254740992`. Table and CSV output for every other number, including `DOUBLE` columns, is unchanged. In `-o json`, numbers are now passed through exactly as the server sent them instead of being re-encoded from float64; the values are the same, but a `DOUBLE` below 1e-6 or at least 1e21 is now written in plain decimal (`0.0000001`) where earlier releases wrote an exponent (`1e-7`).
- Reject reserved `time` field and tag names, including letter-case variants, before sending JSON writes. Timestamp columns must use lowercase `time`; row timestamps continue to use `t`. This prevents invalid names from causing a partially applied batch on the server.
- Enforce the 64 MiB JSON write input limit when a document ends with whitespace. Oversize input is rejected before upload, including when the bounded read would hide further trailing content.
- Reject HTTP redirects that change the request method, preventing writes and database deletions from reporting success after being redirected to a GET request.
- Preserve connection profile names when reading and writing config files. Mixed-case names remain selectable, dots are treated literally, and profiles whose names differ only in case no longer overwrite each other.
- Report token-secret output errors from `auth token create` and `rotate`. Rotation still attempts an explicitly requested `--save` when stdout fails, including in JSON mode, and reports both errors if output and config saving fail.
- Report stdin read errors from `config create/update --token-stdin` instead of saving a partial token or replacing the error with an empty-input message.
- Reject day-based token expiries above 106751 days before creating or updating a token. These values could overflow to a negative or incorrectly short duration.
- Strip terminal control characters and bidi overrides from table headers and cells, including query results. Printable Unicode and multiline cells are retained, and rendering leaves source values available unchanged for JSON and CSV exports.
- Track backup and restore operations by their kind and start time as well as backup ID when using `--wait`, so a later restore of the same backup cannot supply the result of the operation being awaited.
- Honour `compaction trigger --wait-timeout` during status requests and poll delays, even when the request timeout or poll interval is longer than the remaining wait budget.
