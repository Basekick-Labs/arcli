arcli 27.01.1 surfaces Arc's query truncation and governance row-cap signals and improves sample download failures.

### Changed

- `arcli query` preserves `truncated`, `truncation_reason`, `rows_capped`, and `row_cap` in JSON output. Arrow queries read the corresponding `Arc-Stream-Truncated` and `Arc-Rows-Capped` HTTP trailers after copying the body to stdout.
- Server-reported truncation now exits with status 1 after rendering the received data in table, JSON, CSV, or Arrow mode. Diagnostics go to stderr; stdout remains available for inspection or recovery. A truncated Arrow payload may not parse. Scripts must check the command's exit status before treating an export as complete.
- Governance row caps remain successful with a notice on stderr. The result is complete up to the policy limit. A client-side table/CSV `--limit` does not hide a server truncation error.
- Server-provided truncation reasons and Arrow cap values are sanitized in terminal diagnostics. Original JSON metadata is preserved.

### Fixed

- A failed `sample load` download cancels queued downloads before releasing the failing worker's concurrency slot, including while progress output is blocked. The original HTTP, checksum, or filesystem failure is retained instead of being replaced by a sibling's cancellation error and incorrectly reported as an interruption. No files are imported after a download failure; genuine caller cancellation and deadlines remain distinguishable.

### Compatibility

- **Destructive-command exit status (introduced in 26.09.2):** `arcli db drop` and `arcli config delete` exit 1 when confirmation is declined (`Error: aborted`) or stdin is not a terminal (`Error: confirmation required but stdin is not a terminal; pass --yes`). Neither case deletes anything. Before 26.09.2 these paths printed `Aborted.` and exited 0. Scripts upgrading from an older release must handle the failure status; `--yes` continues to skip confirmation. This behavior was delivered in [PR #24](https://github.com/Basekick-Labs/arcli/pull/24) for [arcli#23](https://github.com/Basekick-Labs/arcli/issues/23).
- Older Arc servers without these optional fields or trailers continue to work without completeness notices. Missing metadata is not a guarantee that the result is complete.
- No configuration keys or command flags are added.

Includes the query signal support contributed by efegokdemir in [PR #48](https://github.com/Basekick-Labs/arcli/pull/48), with follow-up diagnostic sanitization and regression coverage. Part of [Arc #726](https://github.com/Basekick-Labs/arc/issues/726).

Includes the sample fail-fast fix contributed by efegokdemir in [PR #50](https://github.com/Basekick-Labs/arcli/pull/50), with follow-up error-preservation and cancellation regression coverage. Related to [issue #42](https://github.com/Basekick-Labs/arcli/issues/42).
